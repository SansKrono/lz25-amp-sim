# File Structure Reference
Complete breakdown of the repository layout, major source files, and their responsibilities.

## Prerequisites
- Comfortable navigating a JUCE/CMake C++ project
- Familiarity with basic JUCE module layout

## Overview
The project follows a typical JUCE plugin structure with source/ containing the processor, editor, panels, and DSP effects. External modules live under JUCE/ and modules/. Build scaffolding is CMake-based with generated build trees in cmake-build-*/ and out/.

## Top-Level Layout
- CMakeLists.txt — main build script
- JUCE/ — JUCE submodule with modules and examples
- modules/melatonin_inspector — Dev-time UI inspector module
- source/ — All project source code
- assets/ — Images and other assets used by the GUI (embedded via BinaryData)
- tests/, benchmarks/ — Unit tests and performance benchmarks
- packaging/ — Packaging scripts or metadata

Generated build directories (do not edit):
- cmake-build-debug/, out/, Builds/, cmake-build-debug/modules, etc.

## Core Source Files
- source/PluginProcessor.h/.cpp
  - Class LZ25AudioProcessor (AudioProcessor)
  - APVTS setup (createParameterLayout)
  - updateProcessorChain(): configures the juce::dsp::ProcessorChain (HPF, waveshaper, tone stack)
  - IR folder/file management (setIRFolder/loadIRFile/nextIR/prevIR)
  - processBlock(): end-to-end DSP including pre-fx, amp chain, IR, gains, and metering

- source/PluginEditor.h/.cpp
  - Class LZ25AudioProcessorEditor (AudioProcessorEditor)
  - Tabbed UI with four tabs: Pitch/Dynamics, Pre-Amp, Amp, Post FX
  - IR controls (prev/next, Load IR/Folder, IR Enable toggle)
  - Tooltip management and melatonin inspector integration
  - Panel enable toggles (double-click tabs)

- source/LookAndFeel.h (referenced in panels)
  - Custom LookAndFeel classes for knobs/tabs

- source/VerticalGradientMeter.h
  - Simple output RMS meter component used in the editor

## Panels (GUI Composition)
- source/AmpPanel.h/.cpp
  - Displays amp face image plus main amp controls: INPUT, PREGAIN, EQ (BASS/MID/TREBLE), PRESENCE, POSTGAIN, RESONANCE, and waveshaper-related sliders (Drive, Asymmetry, etc.).
  - Attaches sliders to APVTS via SliderAttachment

- source/PreFXPanel.h/.cpp
  - Hosts "drive"/pre-amp pedal components: TubeScreamer808, BigCheeseFuzz
  - Lays out pedals responsively with realistic enclosure sizing

- source/PitchDynamicsPanel.h/.cpp
  - Hosts Pitch, SmartGate, TransientShaper, MxrDynaComp in processing order
  - Responsive layout similar to PreFXPanel

- source/PostFXPanel.h/.cpp
  - Placeholder UI for future post-amp effects (delay, reverb, modulation)

## Effects (DSP Pedals)
- source/effects/EffectPedal.h/.cpp
  - Base class for pedals: enable toggle, parameter descriptors, common UI helpers
  - EffectPedalComponent: reusable pedal GUI with enable button and parameter knobs

- source/effects/Pitch.h/.cpp
  - Dual-window pitch shifter (Hann crossfade, modulated delay heads)
  - Parameters: PITCH_PITCH, PITCH_RANGE, PITCH_SHIFT, PITCH_MIX (via MIX in EffectPedalComponent)

- source/effects/SmartGate.h/.cpp
  - Adaptive noise gate with intensity/reduction/release and Djent mode
  - Parameters: SMARTGATE_INTENSITY, SMARTGATE_REDUCTION, SMARTGATE_RELEASE, SMARTGATE_DJENT, SMARTGATE_MIX

- source/effects/TransientShaper.h
  - Pick-attack enhancer using dual envelope follower
  - Parameters: TRANSIENT_ATTACK, TRANSIENT_SUSTAIN, TRANSIENT_MIX, TRANSIENT_CLIP

- source/effects/MxrDynaComp.h/.cpp
  - Classic compressor model with envelope detection and OTA-inspired gain control
  - Parameters: COMP_SENSITIVITY, COMP_OUTPUT, COMP_ENABLE, COMP_MIX

- source/effects/TubeScreamer808.h/.cpp
  - Circuit-inspired TS808 with multiple filtering stages and diode-like nonlinearity
  - Parameters: TS808_DRIVE, TS808_TONE, TS808_LEVEL, TS808_ENABLE, TS808_MIX

- source/effects/BigCheeseFuzz.h/.cpp
  - Lovetone Big Cheese-inspired multi-stage fuzz with mode switch
  - Parameters: BIGCHEESE_FUZZ, BIGCHEESE_TONE, BIGCHEESE_VOLUME, BIGCHEESE_TRIM, BIGCHEESE_SWITCH, BIGCHEESE_ENABLE, BIGCHEESE_MIX

## Assets & BinaryData
- source/images/… and assets/images/… — Images used by the UI
- BinaryData is generated by JUCE’s Projucer or by the build (cmake target juce_binarydata_Assets) and consumed in code (e.g., amp face image in AmpPanel)

## CMake Targets (selected)
- LZ25_VST3, LZ25_AU — Plugin formats
- LZ25_Standalone — Standalone app
- SharedCode, Assets — Library targets used by formats
- Tests — Executable for unit tests
- Benchmarks — Executable for microbenchmarks

## Naming & Conventions
- Parameters use UPPERCASE identifiers; panel toggles use PANEL_ENABLE pattern
- EffectPedal IDs are uppercased and used as prefixes for parameters (e.g., TS808_*)
- GUI components follow JUCE Component pattern and override paint/resized

## Include Dependencies
- Most classes include the minimal JUCE modules they need (e.g., juce_dsp for DSP code)
- Panels include juce_gui_basics and APVTS headers for attachments
